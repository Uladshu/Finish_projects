# 04 — Техническая архитектура

## 1. Принципы

- **Скорость выхода важнее «идеальной» архитектуры**: MVP за 3–4 месяца, минимум своего бэкенда.
- **Один код — две платформы** (iOS + Android) + веб-версия для SEO и тех, кто не ставит приложения.
- **Мультигородность и мультивалютность с первого дня** (город, валюта, часовой пояс — в данных).
- **Локализация персональных данных**: для пользователей РФ — хранение в дата-центре на территории РФ (152-ФЗ),
  для РБ — требования Закона № 99-З. Это влияет на выбор хостинга (см. раздел 3).

## 2. Рекомендуемый стек

| Слой | Вариант A — максимально быстро (рекомендуется для MVP) | Вариант B — «классика» |
|---|---|---|
| Мобильное приложение | **Flutter** или **React Native (Expo)** | то же |
| Веб (лендинг + каталог ситтеров для SEO) | Next.js | Next.js |
| Бэкенд | **Supabase** (PostgreSQL, Auth, Storage, Realtime, Edge Functions) — self-hosted в российском/белорусском облаке | NestJS (Node.js/TypeScript) или Django + PostgreSQL |
| База данных | PostgreSQL + **PostGIS** (поиск по расстоянию) | то же |
| Файлы (фото, видео отчётов) | S3-совместимое хранилище (Yandex Object Storage, Selectel, VK Cloud) | то же |
| Чат / real-time | Supabase Realtime | WebSocket (Socket.IO) + Redis |
| Push-уведомления | Firebase Cloud Messaging + APNs (через OneSignal/Expo Push); для РФ — дублировать в RuStore Push / SMS / Telegram-бот | то же |
| SMS / OTP | SMS.ru, SMSC, SMS Aero (РФ); местные агрегаторы (РБ); вход через Telegram как дешёвая альтернатива | то же |
| Карты и геокодинг | Яндекс Карты MapKit / 2ГИС / OpenStreetMap (MapLibre) | то же |
| Платежи (этап 2) | ЮKassa или CloudPayments (безопасная сделка / выплаты самозанятым); bePaid / Assist для РБ | то же |
| Админка | Retool / Appsmith / Supabase Studio на старте | собственная на React-admin |
| Аналитика | AppMetrica, Amplitude/PostHog (self-hosted) | то же |
| Ошибки | Sentry | Sentry |
| CI/CD | GitHub Actions + Codemagic/EAS Build | то же |

**Почему Supabase**: авторизация, БД, файлы, real-time-чат и Row Level Security «из коробки» —
экономит 1,5–2 месяца бэкенд-разработки. Open-source, его можно развернуть на своём сервере
в нужной юрисдикции. Когда упрёмся в ограничения — постепенно выносим логику в отдельный сервис на NestJS.

## 3. Хостинг и юрисдикция

| Аудитория | Где хранить ПДн | Варианты |
|---|---|---|
| Россия | Только в РФ (первичная запись и хранение) | Yandex Cloud, Selectel, VK Cloud, Timeweb Cloud |
| Беларусь | В РБ / по требованиям 99-З и ОАЦ | beCloud, местные хостинги (уточнить с юристом) |

Практичный путь: отдельная инсталляция (стек одинаковый) на страну, общий код. Это проще, чем
трансграничная передача данных.

## 4. Архитектура (MVP)

```
 ┌──────────────┐   ┌──────────────┐   ┌───────────────┐
 │ iOS / Android│   │  Веб Next.js │   │ Админка Retool│
 └──────┬───────┘   └──────┬───────┘   └───────┬───────┘
        │ HTTPS / WSS      │                   │
        ▼                  ▼                   ▼
 ┌─────────────────────────────────────────────────────┐
 │                    Supabase                         │
 │  Auth (OTP, OAuth)  │ PostgREST API │ Realtime(чат) │
 │  Edge Functions (бронирования, уведомления, модерация)
 │  PostgreSQL + PostGIS + RLS     │  Storage (S3)     │
 └──────────┬───────────────────────────────┬──────────┘
            │                               │
     ┌──────▼──────┐  ┌──────────────┐ ┌────▼─────────┐
     │ Push (FCM/  │  │ SMS-шлюз     │ │ Карты/геокод │
     │ APNs/RuStore│  │              │ │ (Яндекс/2ГИС)│
     └─────────────┘  └──────────────┘ └──────────────┘
```

## 5. Модель данных

Полная схема — в [`db/schema.sql`](../db/schema.sql). Основные сущности:

| Таблица | Назначение |
|---|---|
| `cities` | Город, страна, валюта, часовой пояс |
| `profiles` | Пользователь (связь с `auth.users`), имя, фото, телефон, город, роли |
| `pets` | Питомцы владельца: вид, порода, вес, характер, медицина |
| `sitter_profiles` | Анкета ситтера: описание, тип жилья, условия, локация (PostGIS), статус верификации |
| `sitter_services` | Услуги ситтера и цены (передержка, визит, выгул, …) |
| `availability` | Недоступные даты ситтера |
| `bookings` | Бронирование: владелец, ситтер, услуга, даты, статус, цена |
| `booking_pets` | Какие питомцы в бронировании |
| `conversations`, `messages` | Чат |
| `booking_updates` | Ежедневные фото-/видеоотчёты |
| `reviews` | Двусторонние отзывы с оценкой |
| `verifications` | Документы на проверку (хранятся в приватном бакете) |
| `reports` | Жалобы пользователей |
| `devices` | Push-токены |

## 6. Ключевые API / функции

| Функция | Описание |
|---|---|
| `search_sitters(lat, lng, radius_km, service, start, end, pet_size)` | SQL-функция PostGIS: фильтр по расстоянию, услуге, доступности, размеру животного; сортировка по score |
| `create_booking(...)` | Проверка доступности, создание заявки, push ситтеру |
| `respond_booking(id, accept/decline)` | Смена статуса, уведомление владельцу |
| `start_booking` / `complete_booking` | Перевод статусов (по датам + ручное подтверждение) |
| `post_update(booking_id, media, note)` | Фотоотчёт, push владельцу |
| `leave_review(booking_id, rating, text)` | Только после `completed`, по одному с каждой стороны; публикуются одновременно (обе стороны оставили или прошло 14 дней) — защита от «мести» |
| `submit_verification(...)` | Загрузка документа + селфи в приватный бакет, задача модератору |

## 7. Безопасность

- **Row Level Security** на всех таблицах: пользователь видит свои брони/чаты; документы верификации видит только модератор.
- Телефоны и точные адреса ситтеров **не показываются** до подтверждённой брони; на карте — приблизительная зона (радиус ~300–500 м).
- Фото документов — приватный бакет, автоудаление после проверки (храним только факт и дату верификации).
- Фильтр в чате на номера телефонов/ссылки **не ставим** на бесплатном этапе (оплата всё равно вне платформы), но логируем для антифрода.
- Rate limiting на OTP и отправку сообщений, капча при регистрации.
- Резервные копии БД ежедневно, хранение 30 дней.

## 8. Нефункциональные требования

| Требование | Значение для MVP |
|---|---|
| Время ответа поиска | < 500 мс (p95) |
| Доступность | 99,5 % |
| Нагрузка | до 50 тыс. MAU без переделки архитектуры |
| Размер медиа | фото сжимаются на клиенте до ~1 Мп, видео ≤ 30 сек |
| Офлайн | кэш профиля, списка бронирований и чата |

## 9. Ориентировочная стоимость инфраструктуры (MVP, в месяц)

| Статья | ₽/мес |
|---|---|
| Сервер/облако под Supabase (2–4 vCPU, 8 ГБ RAM) + БД | 5 000–15 000 |
| Объектное хранилище + CDN | 1 000–5 000 |
| SMS (OTP) | 3 000–15 000 (зависит от регистраций; снижать через Telegram/звонок-OTP) |
| Карты (коммерческая лицензия, если нужна) | 0–15 000 |
| Apple Developer / Google Play / RuStore | ~$99/год + $25 разово |
| Sentry, аналитика | 0 (бесплатные тарифы / self-hosted) |
| **Итого** | **≈ 10 000–50 000 ₽/мес** |
